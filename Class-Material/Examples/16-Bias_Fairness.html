3. Fit a Predictive Model

We’ll use a logistic regression model for 10-year CHD risk.

split <- initial_split(df, prop = 0.8, strata = TenYearCHD)
train <- training(split)
test  <- testing(split)

rec <- recipe(TenYearCHD ~ age + sex + education + cigsPerDay + totChol + sysBP + glucose + BPMeds, data = train) %>%
  step_normalize(all_numeric_predictors())

  set_engine("glm")

6. Fairness Metrics via fairmodels

We can use the fairmodels package to audit group-level fairness.

# Extract plain model for fairmodels
glm_fit <- extract_fit_parsnip(fit_glm)$fit

# Prepare test data
prep_rec <- prep(rec)
test_baked <- bake(prep_rec, new_data = test, composition = "data.frame")

# Prepare explainer
# Convert factor outcome to numeric 0/1 for DALEX + fairmodels
y_num <- ifelse(test_baked$TenYearCHD == "CHD", 1, 0)

# Create explainer
expl <- DALEX::explain(
  model = glm_fit,
  data = select(test_baked, -TenYearCHD),
  y = y_num,   # <-- numeric target
  label = "Logistic Regression"
)

Each bar in the plot corresponds to one fairness metric (e.g., Accuracy equality ratio, Equal Opportunity, Predictive Parity, etc.), and the height of the bar shows how unequal the model’s performance is across the groups. The absolute difference in the metric between the privileged group (e.g., Male) and the protected group (e.g., Female).

• A score close to 0 means the model behaves similarly for both groups — i.e., fair under that criterion.

• A large score means there’s a large disparity between groups — i.e., potentially unfair.

So the bars measure the degree of inequality, not the performance itself.

8. Mitigation

a. Group-specific decision thresholds

Even after training, you can still mitigate bias by choosing different cutoffs for different demographic groups. This is often done to equalize a fairness metric such as True Positive Rate (Equal Opportunity).

# Compute ROC curves for each group
roc_male   <- roc(response = test$TenYearCHD[test$sex == "Male"], 
                  predictor = preds$.pred_CHD[test$sex == "Male"], 
                  levels = c("NoCHD", "CHD"))

roc_female <- roc(response = test$TenYearCHD[test$sex == "Female"], 
                  predictor = preds$.pred_CHD[test$sex == "Female"], 
                  levels = c("NoCHD", "CHD"))

# Choose thresholds that equalize TPRs (example: pick threshold with ~0.60 sensitivity)
# Helper function
approx_sens <- function(roc_obj, target) {
  df <- data.frame(sens = roc_obj$sensitivities, thresh = roc_obj$thresholds)
  approx(x = df$sens, y = df$thresh, xout = target, ties = mean)$y
}

th_male   <- approx_sens(roc_male, 0.60)
th_female <- approx_sens(roc_female, 0.60)

b. Reweighting by Sex

A simple fairness intervention is to reweight the training data so that both sexes contribute equally.

# Compute weights inversely proportional to group frequency
train <- train %>%
  mutate(weight = 1 / (table(sex)[sex] / nrow(train)))

# Refit weighted logistic regression
fit_weighted <- glm(TenYearCHD ~ age + sex + education + cigsPerDay + totChol + sysBP + glucose + BPMeds,
                    data = train, family = binomial, weights = weight)

c. SMOTE (Synthetic Minority Oversampling Technique)

The Framingham data (or any CHD dataset) tends to have far fewer “CHD” cases (positives) than “NoCHD” (negatives). This imbalance can cause the model to favor the majority class — often disadvantaging underrepresented subgroups (e.g., females).

library(themis)  # for SMOTE

# Recipe with SMOTE
rec_smote <- recipe(TenYearCHD ~ age + sex + education + cigsPerDay + totChol + sysBP + glucose + BPMeds, data = train) %>%
  step_dummy(all_nominal_predictors()) %>%        # convert factors to dummies
  step_normalize(all_numeric_predictors()) %>% 
  step_smote(TenYearCHD, over_ratio = 1)          # oversample minority class via SMOTE

# Fit the same logistic model
wf_smote <- workflow() %>%
  add_recipe(rec_smote) %>%
  add_model(logistic_reg() %>% set_engine("glm"))

fit_smote <- fit(wf_smote, data = train)

# Check new class balance
train_balanced <- bake(prep(rec_smote), new_data = NULL)
table(train_balanced$TenYearCHD)
## 
## NoCHD   CHD 
##  2485  2485
# Predictions
preds_smote <- predict(fit_smote, new_data = test, type = "prob") %>%
  bind_cols(predict(fit_smote, new_data = test, type = "class")) %>%
  bind_cols(test %>% select(TenYearCHD, sex, education))

What’s happening:

• step_smote() synthetically generates new minority-class examples by interpolating between nearest neighbors in feature space.

• over_ratio = 1 roughly equalizes positives and negatives.

• This step can reduce overall bias in model learning before you even consider fairness metrics.

SMOTE summary:

  • Used when the outcome classes are highly imbalanced (e.g., few CHD cases).

  • Generates synthetic minority samples between nearest neighbors.

  • Balances training data to reduce bias toward the majority outcome.

  • Limitations: may distort feature distributions; does not address demographic bias.

9. Discussion

  • Bias detection: unequal AUCs, sensitivities, or calibration across groups indicate potential bias.
  • Bias mitigation: reweighting or fairness-constrained optimization can reduce disparities.
  • Trade-off: improvements in fairness may slightly reduce overall accuracy.
  • Public-health relevance: equitable performance is crucial when models guide screening or resource allocation.
